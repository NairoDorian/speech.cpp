# speech.cpp — lessons learned

> **What this is:** the single index of hard-won lessons for anyone (human or agent) working on speech.cpp.
>
> **The end goal and the non-negotiable rules (R1–R11) are in [`PLAN.md`](PLAN.md) → *North star*.** Lessons explain *why* those rules exist.
>
> **Rules for this file:**
> - **Every heading states the whole lesson**, so the table of contents alone is useful.
> - Each entry has *what happened*, *why it matters* and *how to apply it*: the gate, grep or habit that prevents a repeat.
> - Add new lessons in the right section. Never append a session diary here — diaries go to `CHANGELOG.md`.
> - When a lesson becomes a lint or test gate, write **GATE:** and the test name, so it can't silently rot.
>
> Sources: the project's own history (2026-08 → 2026-09), the 2026-09-26 checkpoint audit ([`docs/reports/checkpoint_2026-09-26.md`](docs/reports/checkpoint_2026-09-26.md)), and CrispASR's LEARNINGS ([`docs/reports/crispasr/crispasr_architecture_review_2026-09-26.md`](docs/reports/crispasr/crispasr_architecture_review_2026-09-26.md) §5.1).

## A. Verifying claims (process)

### A1. A status claim is unverified until you reproduce it — docs in this repo have repeatedly claimed work that was not done
- **What happened:**
  - Phase 10 was marked "[x] DONE" when its central deliverable (0 of 5 loser-feature merges, 0 arch deletions) had not been executed.
  - Phase 8 was certified on tests that were never compiled.
  - Whisper GGUFs were declared "nonexistent" when they were only absent from one HF repo.
- **How to apply:**
  - Before building on any "DONE", run the gate the claim cites.
  - If no runnable gate is cited, the claim is `[UNVERIFIED]`.
  - Status sections are generated by `scripts/status.sh` (see PLAN.md §2), not hand-written.

### A2. "Environment/asset issue" labels have been wrong 5 out of 5 times — reproduce and root-cause before accepting one
- **What happened:** the causes turned out to be:
  - flashsr: a dropped ggml fork delta;
  - the WER gap: a model unfetched by design;
  - three tests: cwd-dependent registrations;
  - server_model_installer: two real product bugs (Windows `cmd /c` quote stripping; suspended child processes pinning pipes).
- **Cheap discriminators:**
  - Run from the repo root (is it cwd-dependent?).
  - Compare CPU and CUDA: an identical failure means a backend-independent graph cause.
  - Read the test: it may build synthetic fixtures and need no model at all.

### A3. A test that cannot fail certifies nothing — bare `assert()` is compiled out in the Release suite, and unregistered tests never run
- **What happened:** 8 files / 129 checks were no-ops under NDEBUG. Making them live exposed a TokenizerHub bug and a wrong mel bound. The Phase-8 trio and the Whisper C-ABI smokes were never registered.
- **How to apply:**
  - Use a counting CHECK macro, or put `#undef NDEBUG` before the first include.
  - Confirm the test appears in `ctest -N`.
  - Make one check fail on purpose once.
  - Missing models must return the SKIP code, not 0.

### A4. Measure the real flow (C ABI + run_batch), not just the engine session — every earlier gate missed the defects the real flow exposed
- **What happened (qwen3_asr):** the C ABI could not open *any* audio.cpp GGUF. Registry auto-detect picked Silero for any GGUF. Batch ≥ 2 threw. `request_abort()` was ignored.
- **What happened (Whisper, B16c):** four adapter-mapping defects had silently hit every earlier retirement.
- **How to apply:** a family retirement starts with a byte-exact C-ABI-vs-engine test.

### A5. A parent commit can hide a regression — run the failing gate on the parent itself and bisect before adopting or blaming
- **What happened:** transcribe.cpp `6c767184` (subject line "VAD, C++23, Rust bindings") enabled a static step-decode graph on CPU that produced garbage Whisper output. Triage had marked it DEFER for an unrelated reason.
- **How to apply:**
  - Run the same test on the parent at HEAD and at the last triaged commit.
  - Record DO-NOT-ADOPT hunks in the triage ledger.

### A6. Docs that must be updated by hand in five places will drift — generate status and keep one plan
- **What happened:** before 2026-09-26 there were two master plans (373 KB), a 65 KB tracker and an 89 KB progress log. They disagreed with each other and with the tree: the roadmap inventory still read "42 models / 3,305 CMake lines / 7 patches" when the real numbers were 102 / 5,331 / 15.
- **How to apply:**
  - One plan (`PLAN.md`) and one ledger (`docs/LEDGER.md`).
  - Status comes from commands.
  - Diaries go to `CHANGELOG.md` only.
  - Everything older is in `docs/archive/`.

### A7. A plan's ordering exists for a reason — when execution inverts it, stop and record the deviation instead of drifting
- **What happened:**
  - v6 ordered 11a (shared ASR layer) → 12 (`speech.h`) → 11b (ports), so every port would land once, on the final ABI and the shared layer.
  - The 2026-09-24/25 batch ported six families first. Three of them declare private `KvCache` structs, which is exactly what 11a was meant to prevent.
- **How to apply:** every phase has a grep or test gate that the *next* phase's work must not violate. Check it before starting.

### A8. Uncommitted work on a main-only workflow is at risk — commit after each green suite
- **What happened:** two days and seven families of work sat uncommitted with no recorded suite result.
- **How to apply:** once a suite is green, ask the user for the go-ahead and commit. Never leave a session with unverified, uncommitted work without saying so explicitly in the handover.

### A9. A fix is only real if the file it touches is compiled and registered — check the build graph before "fixing" a test
- **What happened:** `c562b7aa` "made `test-omtd.cpp` live" with `#undef NDEBUG`, but no CMake target compiles that file. `capi_test` is built but has no `add_test`, and prints SKIP while returning 0.
- **GATE (PLAN S1.5):** orphan-test lint, meaning every `tests/**/*.c*` is referenced by a target and appears in `ctest -N`.

### A10. A gate's bound must be explicit at registration — defaults drift away from the comment that justifies them
- **What happened:** every WER gate defaulted to 10 % while its comment said "the 3/69 baseline is the bar". On a 69-word corpus that let a 4–7× regression pass.
- **How to apply:**
  - Registrations pass `baseline edits + 1`.
  - A missing bound is an error.
  - Gates only ratchet (L8).

### A11. Copying a file means copying what it depends on — dead links, foreign paths and orphaned fixtures are the residue of wholesale copies
- **What happened:**
  - The README came over from transcribe.cpp with 20 dead `docs/models/*` links.
  - `capi/test/` carried `C:/Users/56579/...` and `D:\audiocpp_test` scripts.
  - `tests/golden/batch/*.json` was keyed by `/Users/cj/...` paths and referenced by nothing.
- **GATE (PLAN S1.5):** a Markdown link check plus a ban on absolute user paths in tracked non-fixture files.

### A12. A header comment or doc that claims more than the code does is a bug — fix the claim or fix the code, the same day
- **What happened:**
  - `decode_driver.h` claimed to "eliminate 15 copies" but only shared argmax.
  - "Unified mel DONE" coexisted with two new 700-line verbatim mel copies.
- **How to apply:** a claim of consolidation cites the grep that shows the copies are gone.

### A13. Two surfaces with the same name must be resolved immediately — "freeze and shim later" lets them diverge into incompatibility
- **What happened:**
  - Upstream shipped its own `include/audiocpp.h`, which now coexists with our `capi/include/audiocpp.h`.
  - Both build a library called `audiocpp`.
  - `audiocpp_stream_start/push/finish` have incompatible signatures, a silent crash for any consumer.
  - The two options, `AUDIOCPP_BUILD_C_API` and `AUDIOCPP_BUILD_CAPI`, differ by one underscore.
- **How to apply:** V7-D1 (one ABI, `speech.h`), plus a duplicate-symbol test (PLAN S1.1).

### A14. A first-pass model test loads the model once and runs one short clip — slow default tests don't get run, and unrun tests hide broken work
- **What happened:** every verdict and parity test ran the whole 4-clip corpus several times per side, plus batched passes. `canary_qwen` parity took 379 s, and one run was still going after 35 minutes. The six-port batch sat unverified for two days, and when it was finally run, 10 of 12 verdicts failed.
- **How to apply:**
  - Quick tier by default: one 3.5 s clip, no batch pass, minimal modes.
  - The corpus runs only in `*_full` (`-DSPEECHCPP_FULL_ASR_TESTS=ON`).
  - Whole quick tier: ~4 min.
  - **GATE:** a new model-backed test must register a quick variant.

### A15. When several families fail a parity check with identical text, look for one shared cause before fixing N families
- **What happened (2026-09-26):** canary_qwen, voxtral and canary all produced identical text, yet failed their verdicts on the same adapter contract gaps: no segment end time, missing spec caps, and a `detected_language` policy difference.
- **How to apply:** group failing verdicts by their DIFF signature first. The adapter result mapping is shared by every family (A4).

### A16. A port is only an improvement if it beats both parents on the same GGUF: measure WER and speed against audio.cpp and transcribe.cpp, never against yourself
- **What happened:**
  - Parity tests compared the engine port with the arch it replaces (text equality). None of them measured speed.
  - The cohere engine port ran 23 % slower than the author's transcribe.cpp arch (RTF 0.455 vs 0.37) while "passing".
  - Nothing compared against audio.cpp's own implementation of the same family.
- **How to apply:** follow [`docs/benchmarking.md`](docs/benchmarking.md):
  - FLEURS multilingual subset;
  - ≥ 3 runs, with run 1 as the warm-up (report it, never average it);
  - CPU while developing, all four backends before accepting.
- **GATE:** PLAN rule R10 and 11b step 5.

## B. Upstream and dependency discipline

### B1. speech.cpp is equally a child of audio.cpp and transcribe.cpp — a dependency bump in either parent is ours
- Keep the ggml pin **at or above** both parents' floors.
- Triage transcribe.cpp by hand. It has no git merge-base here, and that is a tooling limitation, not a hierarchy.
- **GATE:** `scripts/sync-deps.sh` reports drift on all sources.

### B2. An upstream sync must end in a recorded merge — content-copying manufactures phantom "N behind" counts forever
- A content-copy leaves the merge-base behind.
- Close with a real merge, or `git merge -s ours` carrying a per-commit disposition ledger.
- **Verify:** `git rev-list --left-right --count HEAD...upstream/main` should show `…/0`.
- **Also:** upstream can *rewrite* a release commit after we merged it (`9bdd1d90` → `4d88768f`, 2026-09). Disposition it as a no-op re-release.

### B3. `external/ggml` is generated — the invariant is `patches/ggml/`, and audio.cpp merges smuggle untracked ggml edits in
- audio.cpp vendors its own hand-edited ggml, so its ggml changes arrive only as untracked edits inside merges. About 1,800 lines were once found unpatched.
- **GATE:** `scripts/sync-ggml.sh --check` after **every** audio.cpp merge.
- A patch must *round-trip*: patch 0007 was corrupt while its content looked fine in the tree. Finish with a real sync run.
- Use full 40-char SHAs.
- Patches are pure LF, while ggml files are mixed CRLF/LF. Beware `sed -i`.

### B4. Porting an audio.cpp ggml commit needs a per-file 3-way merge on LF-normalized bases, and nothing but reading both sides catches op_params slot collisions
- Use `scripts/port-ggml-commit.sh`.
- Then check:
  1. every new `GGML_OP_*` exists in our header;
  2. the op-name tables match the enum order;
  3. op_params slots don't collide;
  4. the signatures of engine callers still match.

### B5. Upstream audio.cpp now builds ASR families and its own C ABI — check upstream first before porting, and offer generic work upstream to shrink the fork
- **What happened:** canary_asr, cohere_asr, moss_transcribe_diarize and nemotron all landed upstream while we were porting the same families from transcribe.cpp (replan of 2026-09-24).
- **How to apply:**
  - Before porting any family, check `git ls-tree upstream/main src/models src/community_models`.
  - Decision D3 (2026-09-26): offer our generic work upstream.

## C. Architecture rules (learned from all three sources)

### C1. One registry feeds every surface — never implement a family twice (CLI path + ABI path)
- **What happened (CrispASR):** 778 `CA_HAVE_` ABI arms re-implement what the CLI adapters already do. The result was 113 arch strings the CLI knew and the ABI didn't, hard-coded sample rates and alias drift.
- **How to apply:** the CLI, server and `speech.h` all call `ModelRegistry` and sessions. No per-family code may live in the ABI layer.

### C2. Families own graphs and assets, never schedulers, KV caches, decode loops, loaders or mel front-ends
- **What happened (CrispASR):** 86 private schedulers. The cached-graph and gallocr traps were then re-learned 5+ times.
- **What happened (our 2026-09 batch):** 3 private KvCaches.
- **GATE:**
  - `grep -rE 'struct +KvCache' include/engine/models` finds nothing but forward declarations of the shared type;
  - `grep -r ggml_backend_sched_new src/models src/community_models` is listed against a shrinking allow-list.

### C3. Configuration lives in model specs and request options — not in environment variables
- **What happened (CrispASR):** 504 distinct `getenv` knobs became the de facto configuration system.
- **How to apply:**
  - An env var is allowed only for debug dumps and test fault hooks.
  - Record the env-var count in status and keep it from growing.

### C4. Every downloadable model is pinned by revision and sha256, and carries its licence as metadata
- **What happened (CrispASR):** `resolve/main` URLs with no hashes.
- **What happened (here):** `scripts/fetch_asr_test_model.py` pins sha256 and deletes mismatches.
- **How to apply:**
  - Specs carry `license` and `commercial_use`.
  - Non-commercial models are opt-in only, never defaults (decision D5).

### C5. A capability flag is a promise — advertising an unimplemented capability disables the safety nets keyed off it
- **What happened (here):** an arch advertised cancellation but ignored `request_abort()`.
- **What happened (CrispASR):** default `transcribe_streaming` fakes partials.
- **How to apply:** each advertised capability has a test that exercises a non-default value of it.

### C6. Never truncate silently (L11) — every segment and stream boundary either processes all audio or reports truncation
- **What happened:** W2a Whisper dropped audio past 30 s.
- **How to apply:** use `AsrLimits` / `truncated` in the result, and assert both in gates.

## D. ggml and numerics traps

### D1. Reused (cached) ggml graphs must re-upload every input on every run — including "constant" positions, masks and rope tables
- **What happened:** Voxtral-Realtime returned "." on the second run of a same-length clip; 21 sites were fixed in `d04fd552`. CrispASR re-learned the same thing (their L14367: gallocr does not protect inputs).
- **How to apply:** **Test:** run one clip twice on one session.

### D2. A cached cgraph is not re-entrant with `ggml_backend_sched` — any other graph on the same scheduler invalidates it
- Source: CrispASR L2458, L2112, L14056.
- **How to apply:** give a cached graph its own scheduler or allocator, or rebuild it.

### D3. Mel layout: MelExtractor writes mel-major — match the graph input's `ne` order or get fluent, confident, wrong text (94% WER)
- `ne[0] == n_mels` needs frame-major (transpose). `ne[0] == n_frames` takes mel-major as is.
- CrispASR saw the same class as cos ≈ 0.3 / −0.15.
- **How to apply:** check this first whenever a new ASR port produces fluent nonsense.

### D4. `ggml_siglu` is `sigmoid(a)*b`, but PyTorch GLU is `a*sigmoid(b)` — use the swapped variant
- Source: CrispASR L3174. It cost them 3 days.

### D5. F16 accumulation silently breaks: `flash_attn_ext` KQ is F16 (the F32 precision hint is ignored on sm_60), and CPU/cuBLAS `MUL_MAT(F16,F32)` saturates above 65504
- **How to apply:**
  - Manual F32 attention is the default for sensitive families; flash is opt-in.
  - Audit CrispASR's ggml patches 1 and 6 against our stack during the ggml bump.

### D6. Binary broadcast of F32 ⊙ F16 aborts on every backend — cast 1-D norm affines to F32
- Source: CrispASR L18623.

### D7. Quantization carve-outs: audio towers stay at ≥ Q8, and `token_embd` stays F16 below Q8 — sub-Q8 towers collapse without any per-layer cliff to bisect
- Source: CrispASR L14237, L3306.
- **How to apply:** make it a per-family spec field.

### D8. Cosine, correlation and peak-match are scale-invariant — every parity check also needs a magnitude check
- Source: CrispASR L1396.

### D9. A reference that shares your runtime's assumption cannot falsify it — the oracle is the original PyTorch model, not another port
- CrispASR is a *second opinion* (three-way check), never the oracle.
- If the engine and PyTorch agree on the same wrong output, the harness input (usually the prompt) is the bug.

### D10. Static/fixed-topology decode graphs on CPU need their own CPU numeric gate before they are enabled
- See A5 (transcribe.cpp `6c767184`).
- Applies to Whisper W2b.3.

### D11. Resampling quality matters: linear interpolation gives about −10 dB alias rejection, polyphase about −89 dB
- Source: CrispASR L260.

### D12. SentencePiece: greedy longest-match is wrong for both Unigram and BPE, `byte_fallback` is mandatory, and converters must never swallow missing merges
- Source: CrispASR L13872, L14129, L2332.

## E. Model and package specifics

### E1. A spec's `files:` sidecar block is correct for in-house GGUFs and wrong only for third-party-pinned GGUFs
- Check with `audiocpp_gguf --inspect` for `embedded_sidecars`.
- Don't rewrite specs catalogue-wide on a pattern.

### E2. Reproduce a package-layout claim with a KV dump before planning on it
- **What happened:** the Sortformer "transcribe-flavoured" package was really NVIDIA's own third layout, which neither parent could open.
- **How to apply:** run `uv run --with gguf python` with `GGUFReader`. It takes a minute.

### E3. Ask which spec the running binary resolves — embedded vs workspace vs builtin
- The build's copy (workspace, else builtin) wins. The embedded copy is only a fallback.

### E4. Parity bar for a port is "== the arch baseline", not the structural 10% bound
- The corpus is 69 words, so 1 word = 1.45 pp. These gates are tripwires, not benchmarks.

## F. Tooling and environment traps

### F1. Heredoc-piped Python loses a backslash level on this machine — write edit scripts to a file
- **What happened:** `'\\0'` became a NUL byte in a C++ source file.
- **How to apply:** after scripted edits, scan for control bytes.

### F2. Call `ctest.exe` directly — `build_env.bat`'s `%*` mangles `|` in `-R` regexes
- Also: linking fails with LNK1104 while a test binary is still running. Finish the suite before rebuilding.

### F3. Routine testing is CPU only (`build-cpu-core`, `build-cpu-asr-abi`); CUDA only for CUDA-specific changes

### F4. Always `uv run` for Python; never bare `python` or `pip`

### F5. Never benchmark on a busy machine, a nearly full disk or a throttling laptop GPU
- Source: CrispASR L1850, L2709.
